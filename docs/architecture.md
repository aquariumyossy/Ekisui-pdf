# 構成

画面は PDF のバイト列を触りません。ワーカーがページの結果を返し、`Session` を書き換えるのは画面のスレッドだけです。

## 比べた形

二つの形を、この作業の中で比べました。別モデルをサブプロセスで同時に走らせる arena は使っていません。

1. 操作の履歴をすべてコマンドとして残し、画面はその再生結果だけを見る形。確定の取り消しには向きますが、この版で必要な不変条件（同じ語句は同じ呼び名、確定は人が押す、保存は別名）を履歴の実装に埋めることになります。
2. 文書・行・ヒットは不変の値にして、正規化、索引、検索、候補、書き出し、検証は純粋な関数にする。変更できる場所は `Session` 一つ（候補のグループ、呼び名、行の修正）だけにする。

採用したのは 2 です。墨消しの安全性は `export_pdf` と `verify_pdf` に集まり、画面はその関数を呼ぶだけです。

## OCR

Windows 用の PaddlePaddle と PyInstaller の組み合わせは、CPU ホイールと DLL の同梱が不安定なため使いません。重みは PP-OCRv5 mobile のまま、ONNX Runtime の `CPUExecutionProvider` だけで実行します。

傾きは投影プロファイルです。90度と270度はページ全体、180度は行の上下判定モデルで、多数が逆さまならページを回して読み直します。小さい傾きは、白黒の分散が増える角度を探します。

スキャンかどうかは、回転後のページに対する画像の面積です。約6割以上を、4千画素以上の画像が占める（複数の画像は約4ポイント刻みで合わせて数える）ときスキャンです。見えている文字があっても読み直します。見えない文字（描画モード3、スパンの alpha が 13 以下）は OCR 後のページにコピーしません。見えている文字は、画像と同じ回転（90度、傾き、180度）で動かし、OCR の行と一緒に検索できます。`image_path` が無いスキャンページは `insert_pdf` せず、保存を拒否します。保存するスキャンページは直した画像から作り直します。墨消しは、その画像の画素と、書き戻した文字の両方を枠の中から消します。書き戻す文字は、検索と同じ文字幅のマスに1字ずつ置くので、行の途中の名前もその枠の中に入ります。画像が大半を占めない文字だけのページは、短くてもその文字を使います。画像の無い空白ページはスキャンにしません。OCR実行は文字を読むだけで、候補は作りません。作り直したページに載っていた自動候補は外し、ドラッグした範囲は元のページからの回転で動かします。候補を出すのはマスキング実行です。もう一度読み取るときは、前の回転を戻してから新しい回転を掛けます。作り直していないページの枠はそのままです。

テキストPDFのヒット位置は、`rawdict` の文字ごとの箱です。スキャンで文字ごとの箱が無いときは、全角（全角スペースを含む）を1、半角を0.5、ASCIIの空白をより狭くして行の幅を分けます。等分割にすると、半角の数字のあとの名前が枠から外れ、検証もその切れ端を見逃します。都道府県で始まる区間は住所候補です。市区町村が続くときは置換（住所A）、機関名や都道府県だけは黒塗りです。

## 墨消し

`apply_redactions(images=PDF_REDACT_IMAGE_PIXELS)` で、枠の下の画像画素と文字を消します。置換は、消したあとに白枠と呼び名を描き、文字レイヤにも書き込みます。黒い矩形を上に重ねるだけでは終わりません。

保存時のメタデータ削除は、文書情報、XMP、添付、JavaScript、サムネイル、注釈を落とし、`garbage=4` の非増分保存にします。不可視の文字レイヤは残します（`scrub` の `hidden_text` は偽）。
